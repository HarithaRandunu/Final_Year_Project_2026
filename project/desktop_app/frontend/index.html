Setup

Detects the tools this app needs, installs what's missing (with your explicit permission per tool), then bootstraps the whole live cluster in one job.

Required tools

Install all of the tools above before bootstrapping the cluster.

Cluster bootstrap

Creates the kind cluster, installs metrics-server + KEDA, deploys the target app, builds and loads all 4 component images, deploys them, and wires the scheduler extender - everything project/live_cluster/README.md Part B otherwise walks through by hand.

Target App

Chooses which application the framework monitors and scales. None of the three modules is hard-wired to TeaStore — Module 1 and the actuator read the target's identity from environment variables, and Module 2 scores nodes, so it is already app-agnostic. Switching target therefore reconfigures the running controllers; it does not rebuild anything.

Currently plugged in

Presets carry a probe path that is already known to work, so there is nothing to fill in. TeaStore restores exactly the configuration this project's Phase 5–7 results were produced under.

Lists every Deployment in the cluster together with the Services that actually route to it (matched the way Kubernetes matches them, by label selector — not by similar names).

Runs kubectl apply -f <path> on a YAML file or a folder of them, so an app that isn't in the cluster yet can become a target. Once it's applied, pick it on the “App already in the cluster” tab. Building an app from source code is out of scope — supply a manifest (or an image reference inside one) instead.

The bundled example (examples/demo-app.yaml) deploys a ~7 MB test web server called demo-whoami, so you can try the whole flow without supplying an app of your own. It needs internet access the first time, to pull the image. Remove it later with kubectl delete -f project/desktop_app/examples/demo-app.yaml.

Live Monitoring

Polls all four live components' own endpoints every 3 seconds through persistent kubectl port-forward tunnels. Every value shown is read from the running system.

Module 1 recomputes on its own 120-second bucket cycle and Module 3 on a 120-second control cycle, so those two lines hold flat between cycles by design - that is the real cadence, not a stalled chart. The actuator only runs during an ablation arm that uses it; "unreachable" there is normal otherwise.

Load generator

Sends requests at random intervals to the target app, so you can watch the framework react. Range defaults to 8-24 req/s - the band Phase 6's capacity probe validated on this host. Separate from the k6 harness the formal ablation trials use.
